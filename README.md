# Автоматизована система обліку роботи птахоферми

Курсова робота з дисципліни «Об'єктно-орієнтоване програмування».
Автор: Павло Павлишин, група Кн-31. Керівник: А. Татомир.

Консольна програма для невеликої птахоферми. Вона веде облік працівників і птиці,
показує, хто з працівників відповідає за кожну особину, зберігає показники
ефективності (несучість, добовий приріст маси) та виводить зведені метрики по фермі
й по персоналу. Дані зберігаються у файлі JSON і відновлюються під час наступного запуску.

## Вимоги

- Python 3.9 або новіший.
- Сторонні бібліотеки для роботи програми не потрібні.
- Для генерації діаграм і пояснювальної записки (каталог `docs/`) потрібні `Pillow` і `python-docx`.

## Запуск

```bash
python main.py
```

Під час першого запуску створюється файл `data/farm.json`. Його можна копіювати для
резервування або видалити, щоб почати облік спочатку.

## Тести

```bash
python -m unittest -v
```

18 автоматичних тестів перевіряють доменні класи, облік ферми, збереження даних і
консольний інтерфейс (через підміну функції `input`).

## Структура проєкту

Кожен клас розміщено в окремому файлі; файли згруповано в пакети за призначенням.

```
kursova/
├── main.py                        # точка входу: App.launch()
├── poultry_farm/
│   ├── errors/                    # FarmError, NotFoundError, ValidationError
│   ├── staff/                     # Employee (абстрактний), Worker, Veterinarian, Manager,
│   │                              # EmployeeFactory
│   ├── birds/                     # Bird (абстрактний), LayingHen, Broiler, Duck,
│   │                              # PerformanceRecord, BirdFactory
│   ├── farm/                      # Farm, EmployeeStats, FarmStats
│   ├── storage/                   # JsonStorage
│   └── ui/                        # App (меню), ConsoleInput (введення з перевіркою)
├── tests/test_farm.py             # автоматичні тести
└── docs/                          # генератор діаграм і пояснювальної записки
```

Залежності між пакетами односпрямовані: `ui` → `storage` → `farm` → `staff`, `birds` → `errors`.
Жоден нижчий рівень не знає про інтерфейс користувача.

## Розрахунки

- Ефективність особини: `E = (S / n) / N × 100 %`, де `S` — сума значень показника,
  `n` — кількість записів, `N` — норма виду (`Bird.NORM`). Без записів `E = 0`.
- Ефективність працівника — середнє значення `E` закріпленої птиці, яка має записи.
- Оплата праці (поліморфний метод `salary`):
  - птахівник: оклад + 15 грн за кожну закріплену птицю;
  - ветеринар: оклад + 25 грн за кожну закріплену птицю;
  - керівник зміни: оклад + 10 % премії, якщо ефективність підопічної птиці не нижча за 100 %.

Норми та ставки задано константами класів (`NORM`, `BONUS_PER_BIRD`, `PREMIUM_RATE`).

## Формат файлу даних

```json
{
  "name": "Птахоферма",
  "next_emp": 3,
  "next_bird": 4,
  "employees": [
    {"type": "Veterinarian", "id": 1, "name": "Олена Мельник", "base_salary": 15000.0}
  ],
  "birds": [
    {"type": "LayingHen", "id": 1, "tag": "UA-001", "birth_date": "2026-03-01",
     "weight_g": 1750.0, "employee_id": 1,
     "records": [{"day": "2026-10-01", "value": 0.82}]}
  ]
}
```

Поле `type` визначає клас, який створить фабрика під час завантаження.
Запис файлу атомарний: дані спершу пишуться у тимчасовий файл, який потім замінює основний.

## Розширення

- **Новий вид птиці:** створити файл у `poultry_farm/birds/` з класом-нащадком `Bird`
  (константи `SPECIES`, `METRIC`, `UNIT`, `NORM` і метод `describe_metric`) та додати
  клас до `BirdFactory.TYPES`. Меню вибору виду оновиться автоматично.
- **Нова посада:** створити нащадка `Employee` з методом `salary` у `poultry_farm/staff/`
  і додати його до `EmployeeFactory.TYPES`.
- **Інше сховище:** написати клас із методами `save(farm)` і `load()` та передати його в `App`.

## Відомі обмеження

- Файл даних повністю завантажується в пам'ять.
- Одночасна робота кількох копій програми з одним файлом не підтримується.
- Видалення птиці та редагування записів показників не винесені в меню
  (`Farm.remove_bird` реалізовано, але в меню не використовується).
